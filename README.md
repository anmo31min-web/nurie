# 数字ぬりえ

静的な JavaScript / Canvas 2D の数字ぬりえです。`index.html` をブラウザで開くか、静的HTTPサーバーで配信してください。インストールやビルドは不要です。

## 変換

長辺512px → 5×5 Bilateral → CIELAB K-means++（最大8色）→ 4近傍連結成分 → 小領域統合 → 番号矩形の検査と再統合 → 領域境界描画。

- Bilateralの色距離重みをLUT化。数字は実Canvas文字メトリクス・縁取り・余白を含め、領域マップで検査します。
- 最小9px（画像座標）の番号が収まる位置を探してから統合し、余裕がある場合だけ文字を大きくします。
- 塗り判定は画面の線ではなく領域IDを参照します。
- 元画像の輝度に5×5 closingを適用したblack-hat差分を装飾線として重ねます。AIや背景の特別扱いはありません。細線は表示を切り替えられます。
- 装飾線には背景の模様も含まれます。見える細線が塗り領域の境界とは限りません。
- 極小・極細の単独領域で番号が収まらない場合は番号を省略し、画面に件数を表示します。
- 添付画像のコピーを `demo.png` として使用。元の `demo.svg` も残しています。

## 操作性の改善（2026-09-26）

- 読み込み・変換失敗時は直前の完成済みパズル状態へ戻ります。進捗、選択色、拡大位置、完了表示を保持します。連続した読み込みでも、変換途中の状態を復元対象にしません。
- ＋／−／全体ボタン、マウスホイール、ドラッグ、2本指ピンチで表示を操作できます。最大6倍。ドラッグとピンチでは塗りません。横画面ではパレットを右に配置します。
- 選択色の未完成領域を淡色と斜線で示します。塗ると斜線が消えます。
- 装飾線は `detail-lines.js` へ分離。closing差分の強弱閾値と8近傍連結成分で弱い孤立点を除き、領域境界より薄く表示します。元画像や塗り領域は変更していません。

### この変更で確認したこと

実Chrome / Playwright、390×844と844×390、DPR 2で確認しました。

- 壊れた画像の読み込み失敗と、変換完了直前に注入したエラーの両方で、モデル状態とCanvas画像が失敗前と一致。その後のタップも成功。
- 連続読み込みの最後が失敗しても、変換前のゲームへ復帰。処理中のホイールで表示状態を変更しない。
- 拡大ボタン、ホイール、ドラッグ、ゆっくりしたドラッグ、CDPの2本指タッチ入力を確認。ドラッグ・ピンチによる誤塗りなし。
- 選択色変更でCanvas表示が変化し、拡大・移動後も狙った領域を塗れることを確認。34領域をポインター操作で塗り、完成表示まで到達。
- 装飾線単体で白紙に線を追加しない、孤立1画素を除去、連続した暗線を保持することを確認。添付画像では装飾線の非透明画素数が38,174から31,887へ減少し、目・口が残ることを画像で確認。
- 未捕捉JavaScript例外0件。構文確認と差分の空白検査も通過。

タッチ入力は自動化による模擬入力です。スマートフォン実機・SafariはNOT_RUN。途中保存や統合方式の変更は今回の対象外です。

## 絵の仕上がりと20色化（2026-09-27）

現在は最大20色で分割します。デモは20色・37領域です。上記の8色版の検証記録は旧版の記録です。

- 同じ番号の全領域を塗ると、その番号の部分に高解像度の元画像の色・陰影・質感が戻ります。番号が未完了の間は単色で表示します。
- 両側が塗られた領域境界は消え、復元した部分には装飾線を重ねません。完成時は元画像だけを表示します。
- 完成時は中央の覆いを廃止。絵の外に小さな「できあがり ♡」と、保存・再開メニューを表示します。
- 各色で幅のある代表領域を残し、細部の番号は実際の文字幅を測って縮めます。デモの極細1領域は2倍以上の拡大で番号マーカーを表示します。このマーカーのみ領域の外にはみ出すことを許容します。
- 20色のパレットは縦画面で横スクロール。自動選択された番号が見える位置へ移動します。

実Chrome / Playwrightで、20色・37領域の完了、番号単位の復元、通常番号36個の領域内配置、完成Canvasと元画像直接描画の全画素一致、PNGダウンロード、横画面、やり直しを確認しました。未捕捉JavaScript例外0件。スマートフォン実機・Safariは未確認です。
